# Changelog

## [28.0.0.0] - Unreleased

### Added

- [#17](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/17): `Quality.Disposition.ChangeItemTracking` changes the lot, serial or package number or the expiration date of one inspection's stock through Microsoft's `Change Item Tracking` disposition (item or warehouse reclassification journal), prepared or posted with `postImmediately=true`. Irreversible when posting, not idempotent; standard posting is bound through `Quality Move Posting ori` (10035272) so a late refusal rolls back lines and entries. Typed refusals before any change; an inspection without lot, serial or package number is refused. Objects: enum extension 10035310 `Quality Track Types ori` (value 10035310), codeunit 10035311 `Quality Track Impl ori`, table 10035312 `Quality Track Access ori` (capability granted by `BIFROST QM Full ori`); tests 97280 `Quality Track Tst ori`, 97281 `Quality Track Fault ori`. Guides in English and Icelandic.

### Fixed

- #39: Raise the Foundation dependency minimum to 28.0.15.6 in both apps and correct the context-sensitive help URL to include `/help/`. Align the standalone help-link checker with the release help instance and add six regression cases. Regenerate the Icelandic XLF order without changing its 198 translations. No new object IDs.

- #36: `Quality.Disposition.MoveInventory` now states that `expectedCount` counts the one inspection named by `inspectionSystemId` (1 per call, not movement lines or entries). Omitting `expectedCount` reads that count and changes nothing only when Require Confirmation for Irreversible Messages is enabled in Bifrost Setup; when that setup is disabled, omission can execute the movement. The unit is in `effect.changes` (as "The expectedCount unit is ...": Foundation strips a feature-app sentence that starts with "expectedCount counts"), the `expectedCount` parameter and en-US/is-IS help. The type stays `irreversible` (it can post inventory). No new object ID (codeunit 10035270; test 97250 `Scenario_Issue36_CountUnit_NamedInEffectParameterAndHelp`).
- #3: Reconcile creation with the merged purchase-return implementation, preserving Microsoft Inspector permissions and both app capabilities. Allocate creation test objects 97240/97242/97244 to avoid collisions with purchase-return tests.
- #3 / PR #28 amendment: creation fixture cleanup now removes only the native Quality Management defaults (setup, number series, results, result conditions, source and field configurations) that seeding created, and preserves pre-existing defaults (tracking table 97216; tests 97240 `Scenario_AC08_FixtureCleanup_*`, fixture message type via 97242).
- #12 / PR #30: missing or invalid `inspectionSystemId` returns `MissingParameter` with parameter details and bilingual recovery guidance across the isolated transaction (codeunit 10035270; tests 97250).

- #31: Purchase-return refusals now provide typed codes, parameter details and translated recovery guidance. Missing or empty inspection IDs use `MissingParameter`; unknown IDs use `RecordNotFound`. App-owned permission, format, source and result checks preserve transaction rollback (codeunit 10035245; tests 97210/97215).

- #5 / PR #32: the base role (10035236) now grants Reopen handler execution (10035256) and read access to its capability marker (10035258), so Read callers can evaluate the disabled action on BC29. Marker writes remain exclusive to Full (10035237); tests 97220/97221 are unchanged.
- #34: `Quality.Inspection.SetTestValue` now returns typed input, access, inspection-not-found and status refusals with actionable structured fields in English and Icelandic (codeunit 10035242; tests 97209). Native Microsoft validation and atomic rollback remain in place.
- #34 / PR #35 amendment: the published `errors` chapter of `Quality.Inspection.SetTestValue` now emits `{code, when, fix}` through the Foundation `ErrorEntry` contract (codeunit 10035242; test 97209 `Scenario_AC03_ErrorsChapter_PublishesStableCodes`).

- [#4](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/4): the Full role (10035237) now includes the non-assignable permission set 10035285, which grants read access to My Notifications (table 1518). Since #32 added Quality Admin, Microsoft offers to assign a finished inspection to the user in interactive sessions and reads that setting; without the grant, `Quality.Inspection.Finish` under the Full role alone failed with a permission error.
- [#4](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/4): enforce the Full app role through empty capability table 10035284, including callers with Foundation API wildcard execution and native inspection permissions. Dispatcher tests verify read/API refusals without changing an inspection. Native Inspector users need Modify permission, not Delete permission. Contract help chapters and notes now have Icelandic translations.

### Added

- `Quality.Disposition.CreatePutAway` creates unregistered internal/warehouse put-away documents through Microsoft disposition; bilingual contracts and guides, capability table and dispatcher tests (#16). Objects: enum extension 10035306, table 10035307, codeunits 10035308–10035309; tests 97276–97279 (reserved block).
- [#11](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/11): `Quality.Inspection.AddPicture` replaces the most recent picture of an open inspection from base64 or owned staging, with byte-decoded JPEG/PNG/BMP validation, a 1 MiB limit, typed refusals, atomic staging/media rollback and Full capability checks. Adds enum extension 10035294, implementation 10035295, capability table 10035296 and processor 10035297; dispatcher tests/fixtures/permission set/enum extension 97264–97267 and bilingual contract/guides. Additional attachment and OneDrive handling is not applied.
- #14: `Quality.Disposition.CreateTransferOrder` creates unposted transfer order(s) for the failed or passed stock of one inspection through the standard `Create Transfer Order` disposition (not idempotent; typed refusals; rollback on any failure; `BIFROST QM Full ori` capability). Objects: enum extension 10035298, codeunits 10035299 and 10035301, table 10035300; tests 97268 (codeunit), 97269 (fault), 97270 (permission set); guides in English and Icelandic.
- #13: `Quality.Disposition.CreatePurchaseReturn` wraps the standard failed-quantity purchase return disposition, with strict inputs, transaction rollback, permission capability, bilingual contract/help and tests (10035244–10035247; tests 97210–97214).

- Repository scaffolded from Bifrost Subscription Billing setup.

- [#3](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/3): `Quality.Inspection.Create` resolves one source record by table ID and SystemId and calls the standard Microsoft creation API, with optional template selection, native generation rules and atomic refusal handling and typed refusals (MissingParameter, InvalidParameter, UnknownParameter, RecordNotFound, PermissionDenied, PreconditionFailed) with parameter, expected and nextStep (codeunits 10035250–10035251, enum extension 10035241 and permission capability table 10035243). Full access and native Quality permissions are required; Read access cannot create inspections. Includes English/Icelandic contract help and regression codeunit 97240.
- [#7](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/7): `Quality.Inspection.CreateReinspection` wraps the native header action with strict source-ID validation, transactional refusal handling, translated discovery/help and full-role authorization (table 10035320, codeunits 10035321–10035322, enum extension 10035323; tests 97207–97208).
- [#5](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/5): `Quality.Inspection.Reopen` (enum extension 10035255, codeunit 10035256, permission marker table 10035258). The type calls `Qlty. Inspection Header.ReopenInspection` and does not write Status or quantities itself. `BIFROST QM Full ori` (10035237) includes `QltyMgmt - Admin` so the role can run the action; Microsoft still requires that admin role, or SUPER, to be assigned to the user. Tests 97220 and 97221.
- [#6](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/6): `Quality.Inspection.SetTestValue` validates a named test and recalculates the open inspection result through Microsoft’s standard methods. Added enum extension 10035241, implementation 10035242, empty write-permission capability table 10035243, Full-role inspector permissions, bilingual help and regression tests and owned fixture helpers 97202–97206. Missing, malformed, unknown and overlong parameters are refused; transaction failures preserve header and line data.
- [#12](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/12): `Quality.Disposition.MoveInventory`, standard disposition interface wrapper with explicit confirmation, atomic item/warehouse posting, capability check and bilingual help (enumextension/codeunit 10035270, capability table 10035271, bound posting codeunit 10035272). Native dispatcher tests and late-failure injection use 97250–97252; the owned MCP fixture builder and explicit test UI use 97253–97254 without changing write guards or licensing.

- [#4](https://github.com/businesscentralal/bc-origo-bifrost-quality-management/issues/4): message type `Quality.Inspection.Finish` (enum extension 10035280, contract 10035281, implementation 10035282, process 10035283, capability table 10035284; test 97230).
